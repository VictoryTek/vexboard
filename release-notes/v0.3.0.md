# v0.3.0

## Added

- **Uptime history and incidents.** Probe retention moved from a fixed row
  count (`probe.max_history`) to a time window (`probe.history_retention_days`,
  default 30 days), so uptime figures are finally comparable across services
  regardless of their probe interval — previously a service probed every 30s
  retained a very different span of history than one probed every 5 minutes.
  Clicking a service card's sparkline now opens a history view with real
  24h/7d/30d uptime percentages, a heartbeat bar, and a derived incident list
  (start, end or "ongoing", duration).
- **Service control: start, stop, restart.** Admins can start, stop, or
  restart a tracked service directly from its history view — systemd units
  over D-Bus, Docker/Podman containers via the Docker API. The server always
  resolves the unit or container itself from the service's id; the client
  never supplies a name directly, and only services already added to the
  dashboard can be controlled. Stop and restart require a second confirming
  click before they fire.
- **Live log tailing.** The same history view can stream a tracked service's
  recent logs live — `journalctl -f` for systemd units, a native log stream
  for containers. Admin-only, off until explicitly opened, and the connection
  closes automatically when the panel or modal closes so a forgotten tab
  can't leave a process or stream running.
- **Notification channels.** Webhook, Discord, ntfy, Telegram, and Gotify
  destinations are now managed from Settings → Notifications instead of
  `config.toml`, with a Test button that reports the real delivery outcome
  instead of assuming success. A new Rules section adds a configurable
  failure threshold (wait for N consecutive failed checks before alerting,
  so one blip doesn't fire an alert) and an optional repeat interval while a
  service stays down; both default to the original alert-immediately,
  never-repeat behavior, so existing setups aren't affected until changed.
- **Config export, import, and Nix generation.** Settings → Backup & Data
  can export groups, services, quick links, and notification destinations as
  one JSON file — passwords and channel secrets are never included — and
  import them back additively; nothing already on the instance is ever
  changed or deleted. A separate "Copy as Nix" export renders the
  discovery/Docker/probe/notification settings this instance is currently
  running as a ready-to-paste `services.vexboard.settings` block, with
  session and webhook secrets excluded.

## Changed

- Settings page rebuilt as a two-pane layout — grouped sections (Interface,
  Services, Administration) down a left rail, one focused pane on the right
  — replacing the previous single-column list. The old page only ever
  exposed 5 controls; this is the layout the Notifications and Backup & Data
  sections above needed to have a real home, and what any settings added
  after them will use too.
