# v0.1.1

## Fixed

- Static asset serving no longer serves stale `index.html` for missing
  content-hashed build files. Previously, after a frontend rebuild, a browser
  holding an old `index.html` could request a `.wasm`/`.js` filename that no
  longer existed on disk; the SPA fallback served `index.html`'s HTML body with
  a `200` for that request, and the browser then failed trying to
  `WebAssembly.instantiate` an HTML payload. Genuinely missing assets now
  return a real `404`.
- Added `Cache-Control` headers to static asset responses: content-hashed
  build artifacts (`<name>-<hash>.js`, `<name>-<hash>_bg.wasm`, hashed CSS) are
  cached forever (`public, max-age=31536000, immutable`), while `index.html`
  and non-hashed static files (`vexboard-logo.png`, `icons-index.json`) are
  served with `no-cache, must-revalidate` so browsers always check for
  updates.
